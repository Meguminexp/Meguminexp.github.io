## 0. 三条前置约定

**① 曲目 id 策略：老 id 全部保留、原地升级，只加 3 个新 id。**
现有 8 个 id（`bgm_warm / quiet / rain / tension / game / hope / ending / memory`）在剧本里被引用 145 次，
因此**一个都不改名、一个都不删**（改名会连带炸掉 145 处引用与测试）。3 个新 id 已在 `audio.js` 载入时
自动注册进 `YJ.BGMS`，所以剧本里直接写 `bgm:'bgm_longing'` 就能通过校验，无需改 `characters.js`。

**② 全曲共用一条核心动机**（"一部作品"而不是拼盘）：
`do–re–mi–sol–mi–re`（音级 `0,1,2,4,2,1`）。5 种变奏（原型／逆行／扩展／倒影低八度／高八度华彩）
按"每走完一遍 8 小节曲式换一种"轮转。所有曲子都是这条动机在不同调式、速度、音色、音区上的表情。

**③ 三次"零点扬起"共用 `bgm_ending`（主题全奏）**，是刻意的贯穿设计：
跨年零点（c7_90）→ 南阳生日零点（c8_173）→ 一周年表白（c10_36）→ 星星结局。
同一主题第三次出现时用 V4 高八度华彩变奏，形成全作的音乐脊柱。

### 三收束的差异化做法（不需要改 engine.js）
`engine.js` 的 `presentEnding()` 会统一 `playBGM('bgm_ending')`，所以三个结局现在**听到的是同一首**。
`audio.js` 已在 `engine:ending` 事件上挂了路由（`YJ.audio.endingMap()` 可查）：

```js
const ENDING_BGM = { star: 'bgm_ending', slow: 'bgm_longing', she_first: 'bgm_quiet' };
```

三种收尾因此是**同一动机的三种密度**：全奏（ending）→ 小调克制（longing）→ 极简留白（quiet）。
若将来直接改 `engine.js`（把 `playBGM('bgm_ending')` 换成按结局 id 选曲），把这段钩子删掉即可。

## 4. 接线注意事项

### 4.1 `beat` 标记的实际语义（已实现，无需剧本配合）

| 标记 | 对配器做的事 | 对音量的包络 | 用法建议 |
|---|---|---|---|
| *（不写 beat）* | 完全按该曲 A/B/C 段落的编排 | 不动 | 默认就让段落结构说话，**大多数节点不用写 beat** |
| `calm` | 只摘掉最亮的闪片层 | 0.6s 回到基准音量 | 需要"收一点"时 |
| `pulse` | 补上律动层（琶音） | 升到 ×1.10，1.6s 回落 | 推进、心跳加快 |
| `swell` | 补上律动＋闪片层，并**延续一整遍 8 小节曲式** | 升到 ×1.28，3.4s 回落 | 扬起/闪光/和好/零点 |
| `drop` | 抽到只剩和弦垫＋低音（骨架） | 0.25s 抽掉 → 静 1.1s → 1.0s 回来 | "音乐被抽掉"的瞬间（被挂断、语音静音、眼泪掉下来） |

要点：
1. **`beat` 从"下一小节"起生效**，不会把正在响的音符切断，所以天然有 0.1~3s 的呼吸延迟。
2. **`beat` 已限流**：同类标记最小间隔 `swell 3.0s / drop 4.0s / pulse 1.0s`（`calm` 不限）。快速连点推进时不会增益抽搐；连续打出的第二个 `swell` 会被忽略（有意）。
3. **`drop` 会自己回来**，不需要再补一个 `calm`。
4. `beat` **只改增益包络与配器层，不创建任何新振荡器**（旧版 `swell` 会叠一层 1318Hz 亮音，是"混在一起"的元凶之一）。

### 4.2 其它
5. **环境音不需要手动清理**：换场景 `ambience:'night'` 会自动淡出上一种（0.45s 交叉），`stopAmbience()` 会真正 stop 掉噪声源（旧版 rain 的 1 小时音源停不掉，是"配乐混在一起"的帮凶之一）。
6. **`bgm_rain` 自带 `rain` 环境音**：若该场景已显式给了 `ambience`，以显式为准。
7. **环境音 id 白名单**：`none / rain / night / cafe / crowd / sea / keyboard / wind / underwater`（后两个是新加的）。
8. **`bgmOn` 关闭时不创建任何发声节点**：`playBGM` 只记住 id，`refresh()` 打开音乐后会从当前进度重新接上；`sfxOn` 关闭时 `sfx()` 一个节点都不建。
9. **不要给同一个节点同时写 `bgm` 和 `beat:'drop'`**（除非确实要"换曲＋立刻抽空"）；换曲本身已有 ~0.95s 交叉淡入淡出。
10. **各声部有硬性音域窗口**（`pad 33–84 / bass 36–55 / arp 40–84 / mel 45–84 / bell 62–84 / counter 33–62`，MIDI）。
    无论换调、换转位、换动机变奏，都不会窜到刺耳的高音区或听不见的低频泥声。

## 6. 已知限制（纯合成、零采样）

- 没有真实钢琴/弦乐音色：所有音色是振荡器＋低通滤波＋包络。**钢琴的击弦瞬态、弦乐的揉弦与呼吸做不出来**，只能靠"三角波＋慢起音"接近。
- 没有混响/延迟效果器的空间感（测试用的 fake AudioContext 不提供 `createConvolver`/`createDelay`，为保持 `file://` 与测试兼容没有引入）。空间感靠"失谐副本（±6 音分）＋高低音区铺开"近似。
- 没有采样，因此**不能有真实的人声和声/合唱**；`bgm_ending` 的"全奏"只是 5 声部宽排列的和弦垫。
- 打击乐完全缺失（noise 源只用于环境音）：`bgm_game`/`bgm_travel` 的律动来自琶音与脉动低音，不是真鼓。
- 旋律是"动机变奏＋节奏型"程序生成的，不存在手写的完整曲式（前奏-主歌-副歌）；胜在统一与不重复，**不会像手写曲子那样有明确的记忆点副歌**。
- 极密集快切（<0.3s 内连切多首）时，被丢弃的更早音轨是**硬 stop**（把 click 风险换成了确定性），听感上可能有一声轻脆响；正常剧情推进（每曲至少停留 1 个节点）不会触发。
- **没有立体声声场**（测试用 fake AudioContext 不提供 `createStereoPanner`）：所有声部都在正中央，靠音区与音色区分层次，缺少左右宽度。
- 各声部的音域窗口（§4.2 第 10 条）是"保底不刺耳"的工程折中：极少数动机变奏的最高音会被整八度折下来，代价是**个别乐句的顶点被削平**（换来的是任何曲子都不会出现 1.5kHz 以上的尖叫音）。
- **爆破类音效没有真实的"空间"**：烟花炸开的"散开感"只能用 3~6kHz 长噪声尾巴近似，做不出真实混响里的多次反射与方向感（没有 `createConvolver`）；听感更接近"在很近的地方炸"，而不是"在城堡上空炸"。
- **铜管 / 风笛是"波形仿制"**：`sawtooth + 低通 + 失谐副本` 能给出铜管的厚度与明亮度，但做不出铜管的起振过冲与风笛的换气声；花车乐句更接近电子管风琴，而不是真实管乐。
- 烟花/呼啸的**频段是有意压窄的**（见 §7）：只让衰减很快的噪声尾巴走 3kHz 以上，避免持续尖峰。换来的是"不刺耳"，代价是金属光泽（彩色感）比真实烟花弱。

### 7.4 "切换与结束必须干净"的机制（旧 bug 的对症下药）

1. **音效"声部"（`sfxVoice` / `killVoice`）**：一次音效建出来的十几个振荡器与噪声源登记在同一个声部上，
   播完（时长 + 0.2s 余量）后统一 `stop()` + `disconnect()`，`_debug().sfxVoices` 归零。
   关掉音效开关时 `refresh()` 会调 `killAllVoices()` 立刻拔掉正在播的声部。
2. **`disc()` 丢 `this` 的老 bug 已修**：旧代码是 `safe(n.disconnect, n)` —— 把方法当裸函数调用，
   浏览器里会抛 `Illegal invocation` 并被 `safe` 静默吞掉，于是**引擎里每一次 `disconnect()` 都是空操作**，
   停止态的节点一直挂在总线上。改成闭包调用 `safe(function () { n.disconnect(); })` 后，
   音轨 / 环境音 / 音效三处的清理才真的生效（这是"干净切换"最容易漏掉的一环）。
3. **环境音床位也要断开**：`killBed()` 现在连 `bed.gain`（这一床的总线增益）一起 `disconnect()`，
   否则每开关一次环境音就留一个空增益节点。
4. **`park` 的事件节点会被回收**：`retireBedNodes()` 在每次事件前摘掉已经播完的节点，
   `bed.nodes` 不会随游玩时长线性增长；`killBed()` 同时清掉 `timer` / `armTimer` / `fadeTimer`
   三个定时器，所以 `stopAmbience()` 之后**不会再有事件自己响起来**。
5. **没有"跑 3600 秒的噪声"**：`park` 的每一层都显式排了 `stop()`（单块 240s，每 232s 续一次）；
   验证脚本对"每个源都有有限的 stop 时间"做了断言（旧版 rain 的 1 小时音源停不掉是反例）。

**硬指标**（`node /tmp/verify-hk-audio.js`：fake AudioContext ＋ fake 定时器中枢）：**65 项断言全通过** ——
5 个新音效播完后活跃源 0 / 未断开节点 0 / 定时器 0；`playAmbience('park')` → `stopAmbience()` 后
活跃源 0 / `ambBeds` 0 / `ambNodes` 0 / `ambTimers` 0；`sfxOn=false` 时 5 个音效各创建 0 个节点；
无 `AudioContext` 时 34 次 API 调用不抛错；`park` 反复开关 5 次活跃源恒为 3（开）→ 0（关）。
